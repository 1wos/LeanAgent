ATP의 전체 흐름

ATP는 주어진 형식 명제의 증명을 자동으로 찾는 과정입니다.

실선: 지금 문제를 푸는 실행·탐색점선: 이후 모델을 개선하는 학습

설명용 공통 모형입니다. 논문마다 행동 단위와 검색·학습을 사용하는 방식은 다릅니다.

ATP가 보는 상태와 세 가지 판단

s = (Γ, G, M, E, H) 증명 중인 상태를 설명하는 모형

현재 무엇을 알고 있는가?

Γ (감마)
지역 변수와 가정
G · 목표
아직 해결하지 못한 증명 목표
M · 미정 값
아직 채워야 하는 값·증명
(metavariable)과 그 할당
E · 환경
선언·import·Lean/Mathlib 버전
H · 이력
지금까지 시도한 증명 행동

① 실행되는가?

현재 상태에서 유효한 행동인가?
Lean 실행으로 확인

② 도움이 되는가?

제한된 예산에서 증명 완성에 유리한가?
경로 평가와 탐색으로 판단

③ 원래 문제를 증명했는가?

목표·가정을 보존하고 완성된 증명인가?
최종 결과와 의존성을 검사

목표 개수가 적다고 항상 더 좋은 상태는 아닙니다. 여러 목표가 같은 미정 값을 공유할 수도 있습니다.

작은 증명에서 각 역할을 보면

상태: 변수와 남은 목표

n : Nat
⊢ n + 0 = n

남은 목표 1개

검색: 사용할 정리

Nat.add_zero
  (n : Nat) : n + 0 = n

생성: 실행할 tactic

exact Nat.add_zero n

설명용 상태 전환입니다. 실제 시스템에서는 Lean 실행과 최종 검증이 필요합니다.

검색한 정리를 실제로 쓸 수 있어야 한다

검색 목적이 다르면, 필요한 정답도 달라집니다.

방법검색하는 것어디에 쓰는가
LeanDojo / ReProver현재 상태에 관련된 정리다음 tactic 생성
LeanHammer목표 전체를 풀 전제 집합Aesop·외부 탐색·Lean 증명 재구성
Lean Refactor적용 조건·예시·메타데이터가 있는 전략기존 증명의 수정 계획

이름을 찾은 다음에는
가정·타입·import·버전이 맞는지 확인합니다.

검색 지표가 좋아져도 증명 성공률이 항상 올라가지는 않습니다. — Lean Finder 통합 실험

다음 tactic을 만들고, 이어갈 경로를 고른다

생성 확률은 ‘모델이 출력할 가능성’이며, 증명 성공 확률과 다릅니다.

① 생성 모델

여러 다음 tactic을 제안

② Lean

실행 후 남은 목표·가정 확인

③ 경로 평가 모델 (critic)

어느 상태를 먼저 이어갈지 평가

예시 목표　x² + y² ≥ 2xy (x, y는 실수)

다음 tactic의 역할실행 후 얻은 상태증명을 이어가기 위한 단서
A · 식을 전개x·x + y·y ≥ 2xy표현은 바뀌었지만
핵심 단서는 아직 필요
B · 보조사실 추가목표는 그대로 두고
0 ≤ (x − y)²를 확보		제곱을 전개하면
원래 부등식으로 연결

A가 더 자주 생성돼도, B의 상태를 먼저 이어갈 수 있습니다.

설명용 예시입니다. critic의 예상은 틀릴 수 있으며, 완성된 증명은 Lean이 검사합니다.
