# 중간 명제형 블록 전략: 규칙 기반 블록 분할과 조합 선택

중간 명제형은 `have`로 중간 사실을 세워 가며 결론에 이르는 증명으로, 최상위 블록 중 `have` 계열 블록이 토큰의 50% 이상인 경우임(Warm-up 4, 10–15번).

이 증명을 블록 트리로 나누고, 컴파일로 확인한 변경 후보 중 서로 겹치지 않으면서 proof token 감소가 가장 큰 조합을 고름. LLM은 쓰지 않으며 같은 입력이면 항상 같은 결과가 나옴. 4, 10–12번은 아직 실행 중이라 우선 13–15번만 정리해서 올림.

수치는 지정 버전에서 측정한 로컬 측정값임. 토큰은 공식 `proof_length` 규칙으로 세지만 공식 Arena 평가 결과는 아님.

## 규칙

1. 스택: 들여쓰기로 블록 트리를 만듦. 블록 하나 = 한 줄 + 그 아래 하위 증명.
2. DFS: 블록별 토큰 합을 구하고, 루트 합 + `:= by` 줄 토큰이 공식 `proof_length`와 같은지 확인함.
3. 해시: 지역 이름을 v0, v1, …로 바꿔 해시가 같은 블록(이름만 다른 중복)을 묶음.
4. 편집 거리 DP: 거의 같은 `have` 블록 쌍과 서로 다른 토큰(함수 인자 후보)을 기록함. 보고만 함.
5. 우선순위 큐: 예상 감소량이 큰 중복 그룹부터 보조정리로 묶어 컴파일해 봄.
6. 메모이제이션: 같은 파일 내용은 다시 컴파일하지 않음(`cache.json`).
7. 트리 DP: 서로 겹치지 않는 후보 조합 중 감소량이 가장 큰 것을 고르고, 한꺼번에 적용해 다시 컴파일함.

후보는 두 종류임.

- 미사용 블록 제거: `linter.unusedVariables.analyzeTactics`가 경고한 `have` 블록을 지우고 컴파일하는 과정을 경고가 없을 때까지 반복함([prune_unused.py](prune_unused.py)).
- 중복 블록을 보조정리로 묶기: 첫 멤버 자리에 `have blk_genK : ∀ (인자), 명제 := by …`를 두고 각 멤버를 `blk_genK 인자`로 바꿈. 예를 들어 15번의 `h₅`(d, e)와 `h₆`(e, f)를 `blk_gen1` 하나로 묶으면 748토큰이 줄어듦.

구현은 규칙 1–4가 [block_tree.py](block_tree.py), 5–7이 [block_dp.py](block_dp.py)임.

## 결과 (13–15번)

| # | 정리 | 시작 | 미사용 블록 제거만 | 규칙 1–7 최종 | 감소율 |
| ---: | --- | ---: | ---: | ---: | ---: |
| 13 | `putnam_1964_a4` | 1,769 | 1,749 | 1,721 | 2.71% |
| 14 | `putnam_1964_b2` | 1,754 | 1,534 | 1,534 | 12.54% |
| 15 | `putnam_1995_a3` | 4,085 | 3,918 | 3,130 | 23.38% |

- 시작 토큰은 공식 `proof_length`와 같음.
- 최종 증명은 대회 데이터의 header(`import Mathlib` 등) 그대로 컴파일되고, 공리는 `propext`, `Classical.choice`, `Quot.sound`임.
- 트리 DP의 예측 감소량과 다시 센 감소량이 같음(48, 220, 955).
- 최종 증명은 `results/dpK/final.lean`에 있음. 후보별 컴파일 결과는 `cache.json`, 고른 조합은 `result.json`에 있음.
- 묶지 못한 중복: 14번 그룹 1–4는 다른 부분이 `A`/`Aᶜ` 같은 식이라 인자로 바꿀 수 없음. 14번 그룹 5와 15번 그룹 2·3은 `have 이름 : 명제 := by` 한 줄 형식이 아님.

## 신뢰구간

문제 하나의 감소율을 표본 하나로 본 평균 감소율의 95% 구간임([reduction_ci.py](reduction_ci.py)). 컴파일과 토큰 수는 결정적이라 구간은 문제 간 변동만 반영함.

| n | 평균 | 95% t 구간 | 95% 부트스트랩 구간 |
| ---: | ---: | --- | --- |
| 3 | 12.88% | −12.80%–38.56% | 2.71%–23.38% |

n = 3이라 참고용임. 4, 10–12번을 더해 n = 7로 다시 계산할 예정.

## 환경과 한계

- Lean v4.26.0, Mathlib v4.26.0(커밋 `2df2f01`, [project/](project/)로 고정), `lake env lean`.
- 린터가 일부 미사용 변수를 놓칠 수 있어(false negatives) 미사용 블록 제거 결과는 하한임.
- 보조정리로 묶기는 이름만 다른 블록만 다룸.
- heartbeat는 재지 않음.

## 이번 주에 제안한 것

지난주에는 14, 15번 증명을 블록으로 나누고 블록 조합별 토큰을 잼. 이번 주에는 블록을 나누고 고르는 방법을 규칙으로 정해 자동화함.

- 중복된 블록은 하나로 통합하고, 재귀 함수처럼 블록을 함수 하나로 묶음.
- 스택, 해시, 큐 자료구조로 블록을 나누고 찾고 시도 순서를 정함.
- 블록 조합 선택은 DP로 함.
- 자동 단계는 미사용 `have` 반복 제거로 한정하고, 목표는 토큰만 봄(heartbeat 제외).
- 기대 효과는 문제 간 변동 기준 신뢰구간으로 냄.
