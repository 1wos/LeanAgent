두 문제의 공통점

줄어든 곳은 tactic이 아니라 "어떤 중간 사실을 세우나"였습니다

  1. 같은 논증의 반복 · 15번 h₅·h₆ 1,624 → 135, 14번 A·Aᶜ에 대한 두 블록 256 + 256 → 72

Lean 린터 경고(this tactic is never executed, tactic does nothing, This simp argument is unused)는 tactic·simp 인자 단위라, 블록 단위의 반복이나 안 쓰는 have는 따로 찾아야 함.

intro d e f h
obtain ⟨-, h₃⟩ := (hrelation d e).mp h.1
obtain ⟨-, h₄⟩ := (hrelation e f).mp h.2
…  exact h₉

-- A  (key는 수정한 증명에서, 각 have 2줄은 새로 씀)
have key : ∀ x y i,
    digits_to_num (fun j => if j = i then y j else x j)
      = digits_to_num x + (y i - x i) * 10 ^ (i:ℕ) :=
  … 수정한 증명의 key 증명 …
have h₅ : … := fun i => by
  have := h₃ i
  rwa [key, add_comm] at this
have h₆ : … := (같은 2줄, h₄)
-- B  (이번 실험용으로 새로 씀)
have h₇ : 7 ∣ digits_to_num e + digits_to_num d := by

길이 감소율 = 토큰 감소 ÷ 참조 증명 4,085

  • 확인: 32개 조합 모두 로컬 v4.26.0에서 컴파일, 공리 표준 3개. 전체 import Mathlib이 아니라 필요한 모듈만 import함. 모든 블록이 참조 증명인 조합은 4,085토큰으로 공식 값과 같음
  • 결과: 32개 조합 모두에서 토큰 = 4,085 − 바꾼 블록들의 감소 합. 블록끼리 상호작용 0
  • 이유: proof_length는 줄마다 센 값을 더하고, 각 블록은 자기 줄만 바꿈
  • 뜻: 길이 축의 기여는 블록 하나씩 바꿔 재면 그대로 나눠짐
heartbeat 감소율과 zero-shot 호환성은 공식 채점 환경에서 재지 않아 넣지 않음.

비교하거나 다시 실행할 때

고려할 점

  1. proof token은 공식 proof_length 규칙으로 셈. 재구현이 공식 값을 재현하는지 먼저 확인
  2. heartbeat는 같은 버전·import·옵션에서 잰 값끼리만 비교. 공식 값은 제출로만 알 수 있음
  3. 후보는 명제가 같고, sorry가 없고, 컴파일되는지 먼저 확인. 지정 버전 중 그대로 컴파일되는 비율은 zero-shot %로 따로 점수에 들어감
  4. 변경은 증명의 줄 범위와 함께 기록하고, 효과를 나누려면 한 번에 하나씩 바꿔 잼
