학습 출발점

식이 어떻게 바뀌는지,
그 증거가 무엇인지부터

이름의미읽는 예시
refl그대로 두는 축약a ⇒ a
red_I / K / SI/K/S 규칙을 적용하는 증거I ⬝ x ⇒ x
par두 부분의 축약 증거를 합치기a ⬝ b ⇒ a′ ⬝ b′
cases / case증거가 만들어진 규칙별로 경우 나누기cases h₁ → case refl
.par (.red_I K) (.refl S)
-- (I ⬝ K) ⬝ S ⇒ K ⬝ S
-- 왼쪽을 바꾸고, 오른쪽은 그대로 둔 뒤 합친다.

⬝는 적용. ⇒는 이 발표의 설명용 병렬 축약 표기입니다. red는 reduction, par는 parallel, refl은 reflexivity.

WARMUP 08 / Cslib

두 축약 결과를
공통 항에서 다시 만나게 한다

DIAMOND 성질

a ⇒ a₁    a ⇒ a₂

공통 항 b를 선택하여

a₁ ⇒ b    a₂ ⇒ b

결과가 처음부터 같을 필요도,
b가 최종 형태일 필요도 없습니다.

분기마다 만드는 세 가지

  1. 만날 항
  2. 첫 번째 결과에서 가는 증거
  3. 두 번째 결과에서 가는 증거
⟨공통 항, 왼쪽 증거, 오른쪽 증거⟩

양쪽이 par이면 작은 부분항에서 재귀적으로 합류한 뒤 전체를 조립합니다.
정리: Cslib.SKI.parallelReduction_diamond

단일 후보 / 아직 미실험

탐색시키는 대신,
이미 있는 증거를 직접 조립하면?

현재 S/PAR 혼합 분기

apply ParallelReduction.par <;>
  apply ParallelReduction.par <;>
  grind

목표를 나눈 뒤 자동화로
필요한 증거를 찾습니다.

교체 가설

exact .par
  (.par h.1 hb')
  (.par h.2.1 hb')

부분항 축약 증거를
명시적으로 결합합니다.

한 곳만 변경 → 컴파일 → 지표 비교

이 교체 후보는 아직 실행·측정하지 않았습니다. 탐색 제거가 실제 점수 개선을 보장하지 않습니다.

WARMUP 11 / ArkLib

긴 증명은 문법보다
의미 단위로 나눠 읽는다

함수 쪽 fold가, 갱신된 계수로 만든
다음 단계 다항식의 평가와 같음을 증명합니다.

읽을 구조

  1. fiber의 두 점 x₀, x₁ 선택
  2. qMap 평가값과 두 점의 차이 확인
  3. 짝수·홀수 refinement 분해
  4. fold 식과 계수 갱신식 일치

조사할 후보

반복되는 인덱스 산술과 rewrite, 기존 정리로 대체할 전개를 찾습니다.

반복이 보인다는 이유만으로 병목이라고 확정하지 않습니다.

fold_advances_evaluation_poly · 참조 proof 1,906 tokens / 184줄(문제 기록). 상세 구조 최적화와 후보 생성은 향후 작업입니다.

구조 리팩터링 계획

작은 변경 전에,
증명의 의존성을 먼저 본다

분석 질문

  • 핵심 증명 구조를 한 문장으로 설명할 수 있나?
  • 재귀·귀납법은 무엇에 의존하나?
  • 각 cases 분기는 실제로 필요한가?
  • 이미 있는 정리로 대체할 수 있나?
  • 반복 논리를 묶으면 정말 유리한가?

후보는 한 번에 하나

가설 · 예상 효과 · 변경 범위를 먼저 기록합니다.

귀납법 변경이나 보조정리 추가는 검토 항목이지 필수 작업이 아닙니다.

증거와 한계

실행 경로 확인과
최적화 성과는 구분한다

확인한 것

  • 회귀 테스트 20개 통과
  • 8번 원본을 후보로 넣은 실험:
    baseline · candidate 컴파일 통과
  • 8번 대상 정리 sorryAx 의존성 없음
  • 11번 원본 v4.31.0 통과 기록 존재

아직 확인하지 않은 것

  • 최적화 후보의 실제 효과
  • 공식 길이·heartbeat 변화
  • 지정된 모든 버전의 호환성
  • 독립 코드리뷰 승인
  • API 자동 계측·예산 사전 강제

8번 실험은 원본과 동일한 후보로 harness 동작을 확인한 smoke test입니다. 11번 통과는 저장소의 기존 검증 기록을 근거로 하며, 이번 세션의 새 실행 결과가 아닙니다.
