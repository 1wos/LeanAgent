# 후보 선택과 실패 집계에 따른 평가 차이

정소미 · 2026-10-18 · Week 3 실행관리·평가·재현

같은 후보를 평가해도 무엇을 최소화하는지, 실패한 시도를 분모에 넣는지에 따라 결론이 달라질 수 있다. 이번에는 2주차의 4·9번 수정 후보를 모두 다시 검증하고, 논문에서 가져온 평가 방법을 적용했다.

4번 후보 15개와 9번 후보 13개, 참조 증명 2개를 새로 실행했다. 후보 **26/28개**와 참조 2개가 통과했다. 실패한 후보도 집계에 포함했다. 결과를 보며 만들었던 과거 후보를 다시 평가한 후향 분석이다. 새 모델의 생성 성능이나 논문 전체 알고리즘의 성능을 비교한 실험은 아니다.

보고서는 [공통 실험 기록 항목](../../../../meetings/2026-10-11-week2/README.md#후속-실험-정리-제안)에 맞췄다. 대상은 4·9번이며 1–15번 전체 Lean 실험은 수행하지 않았다.

### 실행관리·평가·재현과의 연결

4·9번은 맡은 영역의 기록·평가 기준을 적용해 본 사례다. 논문에서 가져온 원칙과 이번에 작성한 실행 도구를 구분한다.

| 영역 | 답하려는 질문 | 참고한 부분과 이번 적용 |
| --- | --- | --- |
| 실행관리 | 어떤 입력을 몇 번 실행했고, 완료·실패를 어떻게 남겼나? | [ProofOptimizer §2](https://www.alphaxiv.org/pdf/2510.15700)의 후보 수 `k`를 명시한 평가를 참고해 검토 개수를 함께 기록했다. 입력 목록·실행 순서·상태·원시 로그를 남기는 프로그램은 자체 구현이다. 논문의 실행 관리자나 복구 기능을 재현한 것은 아니다. |
| 평가 | 실패와 서로 다른 지표를 어떻게 점수에 반영하나? | [ImProver §4](https://www.alphaxiv.org/pdf/2410.04753)의 실패한 출력 개선량 0, ProofOptimizer의 `min@k / red@k`, [Lean Refactor §4.2](https://www.alphaxiv.org/pdf/2605.20244)의 길이·heartbeat 측정을 적용했다. 정규화 가중합과 Pareto 분석은 이번 분석 규칙이다. |
| 재현 | 같은 결과를 다시 확인하는 데 무엇이 필요한가? | Lean Refactor 부록 J/L의 측정 설정과 [Arvan 등 §3](https://aclanthology.org/2022.emnlp-main.150.pdf#page=2)의 재현 자료 구성을 참고했다. 입력·환경·실행 코드·원시 결과·표 재생성 방법을 제공하며, 같은 환경의 반복 실행을 확인했다. |

## 1. 환경과 기준

| 문제 | 입력 | 고정 환경 |
| --- | --- | --- |
| 4 | 참조 1개, `attempt_01`–`attempt_12`, `research_01`–`research_03` | Lean v4.32.0 · PhysLib `c484336` |
| 9 | 참조 1개, `attempt_01`–`attempt_13` | Lean v4.32.0 · CSLib `197a7be` |

실행 전에 프로젝트·의존성 커밋, 원본 파일, 명제와 후보 파일을 대조했다. 모든 후보는 명제 보존, 금지 패턴, 전체 문맥 컴파일, 공리 목록과 heartbeat 측정을 확인했다. 통과한 선언의 공리는 `[propext, Classical.choice, Quot.sound]`였다. 상세 조건은 [실행 계획](evidence/method-comparison/protocol.json), 실제 환경과 실행 순서는 [환경 기록](evidence/method-comparison/results/pool/environment.json)에 있다.

### 어떤 논문의 어떤 방법을 적용했나

| 논문 | 가져온 방법 | 적용·변경한 부분 |
| --- | --- | --- |
| [ProofOptimizer](https://www.alphaxiv.org/pdf/2510.15700), §2·§5.2.1 | 검증 실패를 원본 비용으로 처리하는 `min@k / red@k`. 비용을 길이 또는 heartbeat로 설정 | 고정 후보 목록의 모든 k개 부분집합을 열거해 평균을 계산했다. 새 모델 표본의 기대 성능으로 해석하지 않는다. |
| [ImProver](https://www.alphaxiv.org/pdf/2410.04753), §4 | 올바른 결과를 얻지 못하면 개선량을 0으로 두어 오류를 반영 | 후보 단위로 적용했다. 길이는 원문의 tactic 호출 수에서 구문 토큰 수로 바꿨다. 성공 후보만 분모에 둔 평균은 별도의 진단용 비교값이다. |
| [Lean Refactor](https://www.alphaxiv.org/pdf/2605.20244), §4.2·부록 J/L | 길이와 heartbeat를 분리해서 측정 | 길이 최소·heartbeat 최소·같은 비중의 정규화 비용을 비교했다. 가중합과 Pareto 분석은 이번 분석 규칙이며, 논문의 전략 검색·재정렬을 구현한 것은 아니다. |
| [Arvan·Pina·Parde, EMNLP 2022](https://aclanthology.org/2022.emnlp-main.150.pdf#page=2), §3 | 입력·환경·원시 결과·표 생성 스크립트를 함께 제공 | 실행 자료와 표 재생성 방법을 묶었다. 산출물 구성에 적용했으며, 별도의 성능 비교 대상은 아니다. |

원문과 적용 방식의 차이 및 계산식은 [실험 안내](evidence/method-comparison/README.md#논문과-계산-방법)에 더 자세히 적었다.

## 2. 비교 조건

후보와 환경을 고정하고 평가·선택 규칙을 바꿨다. `final.lean`은 시도 목록의 후보와 같아서 중복 추가하지 않았다. 기각된 시도와 실패한 시도도 모두 남겼다. 이번 실행에서 새 증명을 생성하거나 수정하지 않았다.

1. **실패 집계:** 성공 후보만 계산한 평균과, 실패를 개선량 0으로 넣고 전체 시도로 나눈 평균을 비교한다. 유효하지만 원본보다 길어진 후보의 음수 개선량은 유지한다.
2. **후보 선택:** 길이 최소, heartbeat 최소, `0.5 × 길이/참조 길이 + 0.5 × heartbeat/참조 heartbeat` 최소를 비교한다. 길이 비중을 0–100%로 바꿨을 때 선택이 달라지는 지점과 Pareto 후보도 계산한다.
3. **검토 후보 수:** k=1·2·4·8·전체에서 `min@k / red@k`를 계산한다. 실패하거나 원본보다 나쁜 후보는 원본으로 되돌린다. 여기서 k는 과거 후보 목록에서 검토할 개수이며, 새 API 호출 횟수나 달러 예산이 아니다.

각 입력은 한 번 새로 검증했다. 실행 순서는 고정 시드로 섞었다. 17건 완료 후 남은 입력은 3개씩 동시에 실행했다. 경과 시간은 운영 기록으로만 남기고 후보 선택이나 속도 개선 주장에 사용하지 않았다.

## 3. 결과와 비용

### 실패를 빼면 평균 개선량이 높아진다

| 문제 | 지표 | 통과/전체 후보 | 성공 후보만 계산 | 실패 포함 계산 | 차이 |
| --- | --- | --- | ---: | ---: | ---: |
| 4 | 길이 | 14/15 | 59.70% | 55.72% | 3.98%p |
| 4 | heartbeat | 14/15 | 66.08% | 61.68% | 4.41%p |
| 9 | 길이 | 12/13 | 47.61% | 43.95% | 3.66%p |
| 9 | heartbeat | 12/13 | 86.79% | 80.11% | 6.68%p |

두 평균은 같은 실행 결과에서 분모만 바꾼 값이다. 실패를 제외하면 실제 시도 전체가 얻은 평균보다 높아진다. 다만 이 성공 비율은 과거 후보 목록의 비율이며, 새로운 모델 호출의 성공 확률이 아니다. ImProver 원문의 정리 단위 점수나 `nonempty improvement`를 그대로 재현했다고 주장하지 않는다.

### 최선 후보는 평가 기준에 따라 달라진다

| 문제 | 선택 기준 | 선택된 시도 | 길이 | heartbeat |
| --- | --- | --- | ---: | ---: |
| 4 | 길이 최소 | research_03 | 123 | 1,411 |
| 4 | heartbeat 최소 | research_03 | 123 | 1,411 |
| 4 | 길이·heartbeat 같은 비중 | research_03 | 123 | 1,411 |
| 9 | 길이 최소 | attempt_12 | 79 | 516 |
| 9 | heartbeat 최소 | attempt_07 | 120 | 353 |
| 9 | 길이·heartbeat 같은 비중 | attempt_12 | 79 | 516 |

4번에서는 세 기준의 선택이 같았다. 9번은 길이 최소 후보와 heartbeat 최소 후보가 달랐다. 같은 비중을 사용했다는 정보까지 남겨야 선택 결과를 다시 설명할 수 있다. 이 후보 자체의 개선 성과는 [2주차 기록](report.md)에 있으며, 이번에는 전체 후보를 새로 측정해 선택 규칙을 비교했다.

| 문제 | 길이에 주는 비중 | 선택되는 시도 |
| --- | --- | --- |
| 4 | 0.00%–100.00% | research_03 |
| 9 | 0.00%–20.56% | attempt_07 |
| 9 | 20.56%–100.00% | attempt_12 |

표의 내부 경계에서는 두 후보의 비용이 같다. 경계 동률은 길이가 짧은 후보를 선택한다. 9번의 Pareto 후보는 5개지만, 위 가중합에서 최선으로 선택되는 후보는 2개다. 나머지도 두 지표에서 동시에 더 좋은 후보가 없는 선택지다. 가중합의 최선 하나만 남기면 이런 선택지가 보이지 않는다. 전체 목록은 [Pareto 표](evidence/method-comparison/results/analysis/pareto_frontier.csv)에 있다.

### 검토할 후보 수에 따라 결과도 달라진다

아래는 고정 목록에서 k개를 균등하게 골랐을 때 얻는 최선 길이 감소율의 평균이다. 가능한 부분집합을 전부 계산했다.

| 문제 | k=1 | k=2 | k=4 | k=8 | 전체 후보 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 4 | 55.72% | 74.81% | 83.13% | 84.60% | 85.55% |
| 9 | 44.28% | 57.98% | 64.93% | 67.64% | 68.53% |

9번의 k=1 값이 앞의 실패 포함 평균과 다른 이유는 원본보다 길어진 유효 후보를 처리하는 방식 때문이다. 실패 포함 평균은 음수 개선량을 유지하고, 이 표는 원본으로 되돌려 개선량을 0으로 둔다.

전체 후보 수는 4번 15개, 9번 13개다. 후반 후보는 앞선 실패·성공을 보고 만든 결과여서 독립 표본이 아니다. 이 표를 새 모델의 호출 수별 성능 곡선으로 쓰지 않는다. 같은 고정 후보 목록에서도 검토 개수가 다른 결과를 바로 비교하면 해석이 달라질 수 있다는 사례다. 길이·heartbeat의 `min@k / red@k` 전체 값은 [후보 수별 표](evidence/method-comparison/results/analysis/budget_curve.csv)에 있다.

### 실행량과 비용

공유한 입력 30개의 결과에는 전체 문맥 검사와 heartbeat 계측을 합쳐 완료된 Lean 컴파일 60회가 대응한다. 중단 시 저장되지 않은 실행은 이 횟수에서 제외했다. 준비·중단·재개 구간을 포함한 시작–종료 경과 시간은 413.06초이며 순수 계산 시간으로 해석하지 않는다. 범위 정리 전 예비 실행 14건은 본 결과에 합산하지 않았다.

이번 평가 프로그램의 새 후보 생성·수리를 위한 LLM 호출은 0회이고 추가 LLM API 비용은 US$0다. 과거 후보 생성과 도구·문서 작성 비용을 포함한 전체 비용은 아니다. 2주차 문제별 API 비용이 집계되지 않아 전체 리팩터링 과정의 문제당 US$3 충족 여부는 판단할 수 없다.

## 4. 실패 원인과 해석 범위

이번에 실패한 후보는 4번 `attempt_05`와 9번 `attempt_03`다. 4번은 `ContDiffBump.pos_of_mem_ball`에 전달한 인수의 타입이 맞지 않았고, 9번은 범위 안에 없는 식별자 `t`를 참조했다. 두 후보 모두 컴파일 오류와 `sorryAx`가 확인됐다. heartbeat 출력 자체는 있었지만 실패한 증명의 측정값이므로 유효 지표로 채택하지 않았다. [원시 출력](evidence/method-comparison/results/pool/logs/)을 보존하고, 실패한 시도는 전체 시도 수에 포함했다.

앞서 진행한 [기초 반복 실험](evidence/reproducibility/README.md)에서는 참조·최종 증명을 네 지정 환경에서 각 3회 실행한 24건이 모두 통과했고, 같은 조건의 길이·heartbeat는 일정했다. 별도의 인공 오류 4종도 기대대로 거부됐다. 이는 실행 도구의 기초 확인이며, 이번 후보 목록에서 발생한 실제 실패와 구분한다.

이번 결과는 두 문제의 고정된 과거 후보에 대한 평가 사례다. 새 생성 모델, 논문 전체 에이전트, 다른 컴퓨터에서의 재현, 빈 환경 설치, 시간 초과·중단 복구의 일반적 신뢰성은 검증하지 않았다. 이번 병렬 재개는 이 실행을 마무리한 기록이며 복구 기능의 포괄적인 시험은 아니다.

## 공유할 결론과 재실행 방법

실험 결과에는 **전체 시도 수·실패 수, 선택 지표와 비중, 검토 후보 수, 고정 환경, 원시 결과 위치**를 함께 남기려 한다. 이번 사례에서는 이 정보가 있어야 평균 개선량과 최선 후보가 왜 그렇게 나왔는지 설명할 수 있었다.
