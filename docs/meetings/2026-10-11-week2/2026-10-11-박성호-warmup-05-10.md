# 담당 5·10번: 증명 리팩터링 기록

작성: 박성호 · 검증일: 2026-10-11 · 공유: 2026-10-11 W02 모임

두 문제 모두 명제(`statement`)를 그대로 두고 증명만 바꿔, 원본보다 짧고 가벼운 검증 통과본을 만들었다. 최종본은 사람 개입 없이 원본에서 출발한 자동 파이프라인의 결과이고, API 비용은 문제당 $3 안이다.

| 문제 | 증명 토큰: 원본 → 최종 | heartbeat: 원본 → 최종 | 점수 | API 비용 |
| --- | ---: | ---: | ---: | ---: |
| 5 | 1,372 → **721 (−47.4%)** | 26,817 → **11,188 (−58.3%)** | 0.471 | $2.58 |
| 10 | 1,463 → **484 (−66.9%)** | 15,902 → **8,805 (−44.6%)** | 0.442 | $2.53 |

점수 = 0.5 × 토큰 비율 + 0.5 × heartbeat 비율(원본 = 1, 낮을수록 좋음). 최종 증명: [P05.lean](2026-10-11-박성호-warmup-05-10/P05.lean) · [P10.lean](2026-10-11-박성호-warmup-05-10/P10.lean). 측정값: [metrics.json](2026-10-11-박성호-warmup-05-10/metrics.json).

## 2. 측정 방법

- **토큰:** 주최 측 저장소 [`lean-refactor`](https://github.com/delta-lab-ai/lean-refactor)의 `proof_length()`. Warm-up 15문제 원본 중 14문제에서 공식 `proof_length`와 정확히 같다.
- **heartbeat:** 원래 파일 안에서 대상 선언만 바꿔 끼우고 `set_option Elab.async false` + `#count_heartbeats in`으로 쟀다. 독립 프로세스 3회 모두 같은 값이 나왔다.
- **통과 판정:** 명제 원문 일치, 원본과 수정본의 `#check`·`#print axioms` 출력 동일(`[propext, Classical.choice, Quot.sound]`, `sorryAx` 없음), 대상 정리에 `warningAsError`를 걸어도 진단 0. 5번은 파일 전체 `-DwarningAsError=true`에서도 오류 0이다. 10번 파일은 대상과 무관한 다른 선언에 원래부터 `sorry`와 deprecated 경고가 있어 파일 전체 엄격 모드는 원본부터 실패한다.

## 3. 어떻게 줄였나: 자동 파이프라인

```text
원본 → [주최 측 cc_agent 1라운드: sonnet, 상한 $1.50]
     → [결정적 후처리: LLM 없음]
     → [cc_agent 2라운드: opus, 남은 예산]
     → [결정적 후처리] → 최종
```

- **cc_agent**는 주최 측 베이스라인이다. 정리마다 Claude Code 세션을 띄우고, lean-lsp로 컴파일을 확인하며 증명을 줄인다. 점수 가중치는 길이 0.5, heartbeat 0.5로 두었다.
- **후처리**는 오늘 손으로 해 보며 찾은 규칙이다. 쓰이지 않는 `simp` 인자와 아무 일도 안 하는 tactic 제거, `simp?` 제안으로 `simp only [...]` 고정, `field_simp` → `ring`, `simp only at *` 삭제, `by exact t` → `t`. 변경마다 Lean으로 다시 판정하고 점수가 내려갈 때만 채택한다.
- 규칙의 근거는 openai/math의 Lean 코드 2만 파일 집계다. `have`·`exact`·`rw`가 tactic의 71%이고 `simp`는 5%로, 자동 탐색 대신 정확히 지정하는 스타일이다.

## 4. 문제별 핵심 변화

**5번 (125줄 → 60줄).** 12단계 `calc`가 3단계가 됐다. 미분 계산을 단계마다 식으로 다시 적지 않고, `rw`와 `simp only [...]` 한 묶음으로 이어서 처리한다. 이름 없는 `simp`를 모두 `simp only`로 고정한 것이 heartbeat 감소의 대부분이다. 미분 가능성 부수 조건의 `by simp`는 `by decide`로 바뀌었다.

**10번 (208줄 → 37줄).** 지역 정의 5개와 보조 사실 여러 개를 없앴다. 섬유 합집합의 크기를 직접 세던 긴 블록을 Mathlib의 `Finset.card_biUnion_le_card_mul` 한 번으로 바꿨다. 마지막 산술은 `simp only [...] at h3`와 `omega`로 닫는다. 에이전트가 쓴 deprecated 정리 `mul_le_mul_left'`는 경고 메시지가 알려 준 `_root_.mul_le_mul_right`로 바꿨다.

## 5. 실험 비교

같은 측정 기준으로 잰 점수다(낮을수록 좋음). 에이전트 설정마다 1회 실행이라 차이가 우연일 수 있다.

| 방법 | 5번 | 10번 |
| --- | ---: | ---: |
| 손으로 정리 + openai/math 규칙(대화형) | 0.725 | 0.889 |
| cc_agent, 원래 프롬프트 | 0.849 | 0.686 |
| cc_agent, 규칙을 프롬프트에 추가 | 0.910 | 0.758 |
| cc_agent 결과 + 규칙 후처리 | 0.697 | 0.653 |
| **자동 파이프라인(최종)** | **0.471** | **0.442** |

## 6. 인사이트

1. **규칙은 프롬프트보다 후처리로 붙이는 편이 나았다.** 같은 규칙을 프롬프트에 넣으면 두 문제 모두 나빠졌고, 에이전트 결과 뒤에 기계적으로 적용하면 좋아졌다.
2. **에이전트는 실행마다 편차가 크다.** 최종 실행의 5번 1라운드는 개선 없이 $0.34만 쓰고 멈췄다. 후처리가 그 상태에서도 점수를 0.81까지 내렸고, 2라운드(opus)가 이어받아 0.47까지 갔다.
3. **에이전트는 예산을 다 쓰지 않고 일찍 멈춘다.** 남은 예산으로 2라운드를 돌리는 것이 효과가 컸다.
4. **에이전트는 경고를 무시한다.** 쓰이지 않는 `simp` 인자나 deprecated 정리가 결과에 남는다. 지우는 것만으로 heartbeat가 준다.
5. **짧은 증명이 항상 싼 것은 아니다.** 10번에서 `rw` 두 줄을 `omega`로 바꾼 시도는 토큰이 13% 줄었지만 heartbeat가 1.2% 늘어 기각했다.

## 7. 우리 프로젝트에 적용할 점

- 하네스 = 주최 측 `cc_agent` + 결정적 후처리 + 남은 예산으로 재실행. 후처리는 LLM 비용이 0이다.
- 합격 판정은 명제 일치, 허용 공리, `sorry` 없음, 대상 정리 진단 0으로 둔다.
- 주최 측 `cc_agent`의 `tools/heartbeat.py`는 `omit … in`이 붙은 선언(10번)에서 측정에 실패한다. 측정 명령을 선언에 붙은 `omit`·docstring 앞에 넣도록 고쳐서 썼다. Lean 프로젝트가 `cc_agent/workspace` 밖에 있으면 lean-lsp MCP가 로드되지 않는 점도 주의한다.

## 8. 한계

- 10번은 지정 환경 4개(v4.28.0–v4.31.0) 중 v4.31.0에서만 검증했다. 버전 호환성 점수는 아직 모른다.
- 에이전트는 API 키가 아니라 Claude Code 로그인으로 호출했다. 비용은 `cc_agent`가 정가로 기록한 값이다.
- 공식 평가 서버의 점수가 아니라 로컬 측정이다. 평가 서버가 같은 토큰 함수를 쓰는지는 확인하지 않았다.
